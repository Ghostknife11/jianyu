# FOE Core

Orchestrates Context Firewall projections, public Provider calls, and the opportunity pipeline without importing concrete providers or Jianyu branding.

The JavaScript reference flow requires `approvedWorldQuery` to match the bounded `request.worldQuery` exactly before calling a dynamic WorldBriefProvider. Its v0.1 pre-mapped candidate path requires public `topics` and optionally accepts bounded provider-declared `matchTerms` in the requested language; both are matched to the current interest locally. A child's explicit refusal of an advertised term suppresses that candidate; a caregiver's own refusal is not treated as the child's veto. A plainly caregiver-led plan or external background alone skips external discovery. An untagged provider candidate is not treated as child pull. This compatibility path is not the final versioned feed protocol; see ADRs 0016 and 0024.

The JavaScript `SearchProvider` path uses the same exact public-query approval and local topic/refusal matching. For AI, call `createTaskContext(request, approvedLlmCategories)` to show the specific projected payload, then pass that object as `approvedLlmContext` alongside the categories to `runOpportunityFlow`. The flow recomputes and compares the payload before invoking `LLMProvider`; a changed input or absent approval skips the call. A capability must cover `minimized-task-context` and every approved category. A pure explicit refusal, plainly caregiver-led plan, or obvious external background alone does not initiate AI discovery; an independently positive child clause can. This is a lexical safeguard, not proof of genuine desire or free-text de-identification. See ADRs 0017 and 0024.

The flow also binds each returned candidate's `source.kind` to the Pack or Provider actually invoked before local Gate and diversity processing. A candidate's self-declared source kind is untrusted; source titles, URLs, and factual claims still need their own validation. See ADR 0018.
